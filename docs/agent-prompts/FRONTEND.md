DESIGN DIRECTION — keep it and refine it; do not replace it
The look takes its layout language from format.obys.agency (Awwwards Site of the Day, Oct 2026) and its colours from Indian government file work on light noting-sheet paper:
- Colours (tokens in src/styles.css under @theme): paper #f2f5f0 as the page background and label strip, white sheet #ffffff for documents and cards, ink #1d2b4f for the app header band, primary buttons, rules and text, red tape #b4232c only for deficiencies, the proof-chain ribbon, the FIRE.VALID flag and the wordmark's full stop, turmeric #9a6410 for items awaiting review or authentic-expired status, leaf green for verified, dusk violet for simulated or processing.
- The block-letter wordmark (src/components/BlockWordmark.tsx): prominent in the start-page hero and footer, small in the sticky header and app header.
- The scroll-driven start page (src/pages/Landing.tsx, src/components/journey/DocumentJourney.tsx, src/components/journey/StoryDocument.tsx, src/lib/scrollStory.tsx): one synthetic fire safety NOC (Godavari College of Engineering, FNOC/SYN/2024/3310, valid until 31-03-2026) travels through chapters 0–8 on a sticky right-hand stage while copy scrolls on the left, followed by workspace previews (#product), safeguards (#trust) and the final CTA with its red-tape proof ribbon.
- Sign-in (src/components/SignInDialog.tsx, src/components/SignInCard.tsx, src/pages/Login.tsx): every Sign in control on the start page opens the native modal <dialog>; /login remains the standalone fallback and session-expired redirect target.
- Square corners; chamfers (.cut) instead of rounded cards.
- Type: Inter Display for large headings (tight tracking, leading near 1), Inter for interface text, Lora for explanations and officers' reasons. Parenthesised numbers like (1)–(8) only where the content really is a sequence.
Do not add: decorative gradients, glassmorphism, 3D, ALL-CAPS eyebrow labels, grids of identical cards, emoji, stock photos or charts without real data.
Motion only where it shows something: the scrubbed, reversible document journey driven by scrollStory.ts (transforms and opacity only, one writer per property), the evidence box coming into focus, upload progress, quick page cross-fades. Honour prefers-reduced-motion everywhere (static document still in each chapter). Responsiveness matters more than motion: interactions must answer within 100 ms.

STAGE 2 — NEW AND IMPROVED SCREENS
1. Evidence viewer: move between evidence items with the arrow keys; zoom in, out and reset; page thumbnails for multi-page PDFs; side-by-side view when a finding has evidence on two documents (for example, the affidavit says 300 and the faculty summary says 240).
2. Duplicate-evidence comparison for officers: both images side by side with the perceptual-distance figure. Institution users must never see the other institution's file; the API already withholds it, so do not work around that.
3. Clarification loop: institutions see "Clarification requested" findings with the officer's reason and can reply, optionally linking a newly uploaded document. Officers see replies in the decision step of the proof chain. Uses POST /api/v1/findings/{finding_id}/responses.
4. Notifications in the app shell with an unread count, using GET /api/v1/notifications and POST /api/v1/notifications/{notification_id}/read.
5. Rule-pack diff on /rules comparing any two versions, using GET /api/v1/rules/versions/{from_id}/diff/{to_id}.
6. Queue: sortable columns, search by institution name or Permanent ID, filters kept in the URL.
7. Empty, loading, error and offline states on every screen. A 401 sends the user to sign in with a message; a 403 explains the role limit.
Items 3–5 depend on new backend endpoints (specified in docs/agent-prompts/BACKEND.md, stage 4). If they are not in contracts/api.gen.ts yet, build the UI against a typed mock that follows that spec, keep it behind a clearly named flag, and switch to the real client as soon as the contract includes them. Never ship the mock as live behaviour.

NON-NEGOTIABLE RULES
- Use only endpoints and fields that exist in contracts/api.gen.ts. Never invent an endpoint or a response field; if you need one, write it down for the backend lead.
- Every visible control works. No dead buttons, decorative upload areas, fake progress, made-up analytics or placeholder numbers. Every count and chart comes from the API.
- Wherever a result comes from a simulated source, the "Simulated source" label stays visible.
- The interface never presents approved, rejected, forged, fake or fraud as a system output. Findings are advisory, integrity results are indicators, and officials decide.
- Clause references marked TO_VERIFY keep the "Clause not yet verified" badge.
- No secrets or document contents in client code, logs or analytics. No third-party trackers or CDNs.
